# Wext Static Publisher v3.2.1

## WordPress.org review fixes

- Render static search, language preference, and SEO report assets through isolated WordPress script and stylesheet queues. The live site's queues remain unchanged.
- Move translation catalogs outside the installable plugin. WordPress loads available language packs automatically.
- Wait for the administrator to deactivate Ragnus Static Publisher before migrating; never deactivate another plugin automatically.
- Validate export destinations and reject traversal, symbolic links, server configuration files, and server-executable extensions, including compound extensions.
- Store new installations' artifacts in `wp_upload_dir()` under `wext-static-publisher`. Preserve existing `wext-static` paths for saved archives.
- Protect storage with Apache/IIS access rules and document the required Nginx deny rule.

## Validation

Passed: activation smoke test; legacy migration; language packs; activity logs; archive retention; SmartCrawl integration; unsafe path and symlink rejection; asset queue isolation; complete export of 20 URLs. Storage and asset queue tests also passed on the minimum supported WordPress version, 6.5, with PHP 8.1.

The official Plugin Check run against the packaged plugin reported 0 errors and 81 warnings. The full report is in `wordpress-org/plugin-check-3.2.1.json`. ZIP integrity and absence of bundled PO/MO files and shell build scripts were verified.

JavaScript remains part of exported websites because static search and the site's scripts need it. These are export artifacts, not PHP or WordPress-installed code. Direct access protection on Nginx requires host configuration.
